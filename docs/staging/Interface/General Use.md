The interface should be used as a focused operations workspace, not as a giant raw-data browser.

# Start Narrow

Open the smallest set of channels, tasks, or resources that answers your current question. Expand only when the next step needs more context.

# Keep Context Visible

When operating a live system, keep these nearby:

- the values you are watching
- the task or module state that owns those values
- any command controls you may use
- diagnostics that explain freshness or connection state

# Treat Stale Data Seriously

Stale data means the interface cannot prove the displayed value is current. Before acting on a stale value, check the source task, module, connection, and record state.

# Use Purpose-Built Surfaces

If a plugin provides a page, resource, or task workflow for the job, use that before falling back to raw channel browsing. A good plugin surface usually encodes project-specific names, constraints, and defaults that raw data views cannot know.

# Good Habits

- search before scrolling
- pin or save the values you check repeatedly
- keep wide queries and exports intentional
- verify authority before writing commands
- use task controls instead of editing lower-level channels when a task workflow exists
- use checklists for repeatable procedures instead of relying on memory
